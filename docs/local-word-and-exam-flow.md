# 本地 Word 与自然语言出卷验收（2026-10-21）

当前入口为学习工作台与对话记录。历史题库、错题与计划退出主导航；旧数据与接口保留，当前模拟练习不再附自评组件。每次完成有内容的解答后，在结果下方提供可跳过的整理提示，用户点击后才下载 Word。生成预览也提供下载入口。

## 通用出卷流程

此前“一张试卷”没有匹配出题动作，含“这部分的知识点”的整句也可能被直接用于检索。因此实际有相关正文仍会误走普通问答并报告依据不足。

现在先识别出卷动作，再提取实际知识主题，分流整份资料学习与指定主题生成。“根据这进程这部分的知识点出一张试卷”提取主题“进程”；“根据教材中进程这部分知识点出一张试卷”同样聚焦该主题。缓存淘汰、二叉树等主题复用同一规则。未指定题数的主题试卷默认 5 题，明确题数沿用用户要求；没有历史卷也可依据已上传参考资料生成。

后续仍执行资料范围、题数、题型与引用校验。没有真实来源时保留不足提示，不将模型自行编造的来源保存为成品。PPT / Word / PDF 等泛指资料的出题请求继续走整份资料学习，不能把格式名误当知识主题。

## Word 下载

- `GET /api/courses/{course}/artifacts/{artifact}/word?kind=qa|knowledge`
- `GET /api/courses/{course}/conversations/{conversation}/word?kind=qa|knowledge`

题目版包含题干、选项（如有）、答案、解析及引用；知识版整理已有总结、重点、易错点，纯试卷则使用本次答案与解析中的知识内容。普通问答保留用户提问与现有解答，标明模型或资料依据。两种文件均附已有来源位置与原文节选，较长片段标注截取，不额外请求模型。

导出复用现有课程及账号范围校验，跨课程 ID 不可读取；未完成解答不提供导出。文件由浏览器下载到本机，网页不会自动读取任意本地目录。此功能保留学习成果副本，不提供课程和原始上传文件的完整恢复，也不替代服务端持久化。

## 验证

- 完整回归：`pytest -q` 共 278 项通过；`ruff check app tests scripts/verify_exam_word_api.py` 通过。
- `tests/test_topic_generation.py`：自然章节表述、题数与题型、泛指资料兼容性。
- `tests/test_word_export.py`：端到端出卷及两类 Word 内容、全部题目答案、来源、跨课程拒绝、失败结果拒绝、导出不重复调用模型。
- `scripts/verify_exam_word_api.py`：当前 DeepSeek API + 独立临时课程 + 合成 PPTX，进程与缓存淘汰两个主题均成功生成 5 题，含答案、解析、引用与可读 Word。报告保存在忽略提交的 `data/exam-word-acceptance/report.json`。
- `scripts/browser_local_word.cjs`：真实工作台 SSE 出卷、两个 Word 下载、跳过整理、来源预览、旧导航重定向及 390 / 320px 布局，浏览器未发现 JS 错误。
- 两份真实生成样例用 Microsoft Word 转 PDF，再逐页渲染检查，题目版 3 页、知识版 2 页；来源位置与原文节选保留，题干与答案解析没有跨页割裂。渲染文件位于本地 `data/exam-word-acceptance/`，不随源码上传。

合成资料与工程测试验证流程和来源约束，不代表任意课件都能生成任意数量或难度的有效题目。扫描件的 OCR 质量、原文内容量及模型输出质量仍会影响结果。
