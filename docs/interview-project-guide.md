# StudyAgent 项目面试八股与回答

整理日期：2026-10-10。依据当前 v0.4.0 源码、README 和项目内评估报告。

适合 Python 后端、AI 应用开发、RAG / Agent 岗位。每个问题先给可口述的回答，再给项目证据与追问。参数均指源码默认值，本机环境或保存的连接配置可能覆盖默认值。本文整理资料，未重新执行测试或在线模型验收。

## 先准备一段项目介绍

> 我做的是一个多源学习资料复习助手，支持上传 PDF、PPTX、DOCX，结合课程资料回答问题、检索历史试题、生成复习提纲与模拟练习，并保存练习自评、错题和复习计划。后端使用 Python、FastAPI、SQLAlchemy 和 SQLite，Chroma 保存可重建的向量索引。核心 RAG 链路、工具注册和 Agent 执行循环由项目代码直接实现。设计上重点处理来源可追溯、课程范围隔离、模型输出校验，以及数据库和向量索引之间的失败恢复。目前定位是本机单用户 MVP；默认 demo 使用字词哈希检索和规则规划，API 模式具备模型接入链路，真实模型效果仍需单独验收。

## 一、RAG 与检索：优先掌握

### 1. 什么是 RAG？你的项目为什么使用它？

**回答：** RAG 是先检索外部资料，再把检索结果作为上下文交给模型生成回答。我的项目需要回答用户上传的课程内容，而这些资料不一定在模型训练数据里。检索可以随资料更新，配合原文与位置展示，便于用户核查。

**项目证据：** [检索服务](E:/StudyAgent/app/rag/retriever.py)、[问答服务](E:/StudyAgent/app/services/qa.py)。

**追问：RAG 与微调有什么区别？** RAG 主要解决回答时提供外部知识的问题；微调主要通过训练改变模型行为，两者可以结合。当前项目没有微调。

### 2. 完整 RAG 链路怎么走？

**回答：** 入库侧是上传校验、内容去重、格式解析、文本清洗、切块、Embedding、写向量索引、提交正文和 ready 状态。查询侧是检查课程与资料范围、问题向量化、召回候选、阈值过滤、去重与上下文预算、调用模型、校验引用，最后返回回答与数据库里的真实来源。

**项目证据：** [入库服务](E:/StudyAgent/app/services/ingestion.py)、[检索服务](E:/StudyAgent/app/rag/retriever.py)。

**追问：问答依赖哪些存储？** Chroma 返回 Chunk ID 与距离；SQLite 保存正文、文件信息、位置与处理状态。

### 3. 为什么要切块？块大小和重叠怎么选？

**回答：** 整份文档容易超过输入限制，也会让不同主题混在同一向量里；片段太短则可能丢掉条件、定义与结论。我默认按 800 字符切分、重叠 120 字符，优先寻找后半段的句末或换行边界。这是初始配置，需要根据真实课程的检索评估调优。

**项目证据：** [切块实现](E:/StudyAgent/app/rag/chunker.py)、[默认配置](E:/StudyAgent/app/core/config.py)。

**追问：跨页切块吗？** 当前不跨解析器的原始块拼接，保留位置准确性；代价是跨页语义可能被切断，DOCX 短段落也可能形成小片段。

### 4. 字符数和 Token 数相同吗？

**回答：** 不相同。Token 由具体模型的 tokenizer 决定，中文、英文、标点与数字的切分不同。当前切块和上下文采用字符预算，检索正文默认最多 9000 字符，这属于输入规模控制，不能保证精确满足某个模型的 Token 上限。

**追问：如何改进？** 使用对应模型的 tokenizer，并为系统提示、问题、工具定义、历史消息和输出预留预算。当前还没有精确 Token 预算器。

### 5. Embedding 是什么？demo 也有语义能力吗？

**回答：** Embedding 把文本表示为向量，训练得到的语义模型可以让含义接近的文本在向量空间里更接近。我的 demo 使用 2048 维字词哈希特征：英文按词、中文按相邻双字取特征，哈希映射后做归一化。它主要反映字词重合，没有学习到的语义理解。

**项目证据：** [Embedding Provider](E:/StudyAgent/app/rag/embedding.py)。

**追问：API 输出怎么校验？** 每批最多 16 段，按返回 index 恢复顺序，检查数量、维度、有限数值和非零向量，避免文本与向量错位。

### 6. 余弦相似度是什么？0.8 代表 80% 正确率吗？

**回答：** 余弦相似度为 `a·b / (||a|| ||b||)`，衡量向量方向的接近程度。项目的 Chroma collection 配置 cosine，检索时用 `1 - distance` 得到相似度。相似度既不是答案正确概率，也不能直接比较不同模型的质量。

**追问：为什么归一化？** 对单位向量，点积等于余弦相似度。demo 显式归一化；API 向量没有在本地统一归一化，检索使用 cosine 距离。

**参考：** [Chroma collection 与距离配置](https://docs.trychroma.com/docs/collections/configure)。

### 7. Top-K、候选数与阈值有什么区别？

**回答：** 候选数是向量库先返回多少结果，Top-K 是筛选后最多保留多少来源，阈值控制最低相关程度。项目默认候选 12、最终最多 6、相似度阈值 0.25，还会去掉同文档的完全相同正文，并受字符预算约束，所以最终不一定有 6 条。

**追问：K 越大越好吗？** K 大可能提高证据覆盖，也可能引入噪声并增加输入成本。阈值过高会漏召回，过低会引入不相关片段，应通过开发集实验选择。

### 8. 什么是 HNSW？项目有没有自己实现？

**回答：** HNSW 是通过分层邻近图寻找近邻的近似检索方法，适合在较多向量中加速搜索，存在内存、检索速度与召回率之间的取舍。项目使用 Chroma 的 HNSW 配置，没有自己实现底层算法，也没有做参数调优实验。

**追问：近似与精确检索有什么区别？** 精确检索需要比较全部候选；近似检索减少搜索量，但可能漏掉真正最近的结果。小规模资料仍应先关心解析、切块和证据质量。

**参考：** [Chroma HNSW 配置](https://docs.trychroma.com/docs/collections/configure)。

### 9. 为什么换 Embedding 模型要重建索引？换 LLM 呢？

**回答：** 不同 Embedding 模型生成的向量属于不同空间，即使维度相同也不能直接比较。项目把模式、服务地址、模型名和维度形成指纹，不匹配的文档标记 stale，查询也检查指纹。仅切换生成 LLM 不改变检索空间，现有索引可以继续使用。

**项目证据：** [指纹生成](E:/StudyAgent/app/rag/embedding.py)、[过期标记](E:/StudyAgent/app/services/ingestion.py)、[模型连接](E:/StudyAgent/app/services/connection.py)。

**追问：同名模型在服务端更新呢？** 当前配置指纹无法自动识别服务端偷偷替换的模型版本，后续应增加明确版本标识和重建策略。

### 10. 向量检索、BM25、混合检索和 Rerank 怎么区别？

**回答：** 向量检索用于相近语义；BM25 根据词项匹配与统计权重排序，适合术语和编号；混合检索融合两路候选；Rerank 对已召回的少量候选进一步排序。我的知识检索目前是纯向量基线，没有 BM25、混合召回或 Reranker。

**追问：下一步先做哪个？** 先看失败样本。如果术语匹配差，评估关键词召回；如果相关证据已经召回却排得靠后，再评估重排。不能未经实验就声称能提高多少准确率。

### 11. 检索到相关内容，为什么还可能答不了？

**回答：** 主题相关不等于包含回答所需的信息。例如检索到 A* 的评价函数，不一定能回答 A* 的时间复杂度。项目区分“有召回”和“证据足够”，要求模型证据不足时拒答；没有来源时不调用问答模型。

**项目证据：** [问答服务](E:/StudyAgent/app/services/qa.py)、[问答提示](E:/StudyAgent/app/llm/compatible_provider.py)。

**追问：能完全消除幻觉吗？** 不能。需要分别检查召回、答案事实和证据支持，当前引用检查只覆盖其中一部分。

### 12. 如何保证引用可信？

**回答：** 解析器记录真实位置，服务端给本次上下文分配 S1、S2 等引用 ID。模型只生成正文与引用列表，不能自行编造页码；后端检查引用是否来自实际提供的证据，来源卡片从数据库恢复文件和位置。这样能降低虚假来源风险，但不能证明每句话都被原文支持。

**项目证据：** [Source 结构](E:/StudyAgent/app/schemas/chat.py)、[QA 校验](E:/StudyAgent/app/services/qa.py)、[Agent 校验](E:/StudyAgent/app/agent/tools.py)。

**追问：两条链路校验完全一样吗？** 不完全一样。Agent 的 `valid_answer` 要求声明引用集合等于正文引用集合；QA 检查正文引用是声明引用的子集，仍存在进一步统一校验的空间。

### 13. Prompt Injection 怎么处理？

**回答：** 上传资料与工具返回都属于待分析数据，不能当作系统指令。提示里明确要求忽略资料中的角色切换或执行命令要求；运行时只允许注册工具，参数经过 Schema 校验，课程与资料范围由服务端注入。提示是约束的一层，后端校验才是可执行边界。

**追问：有完整防注入系统吗？** 没有。当前措施降低风险，尚未完成系统性的攻击评估，也没有用户身份与授权体系。

## 二、Agent 与工具调用：项目特色

### 14. RAG 和 Agent 有什么区别？

**回答：** RAG 描述检索证据后生成的方式；Agent 描述根据任务选择工具、读取结果并决定下一步的执行机制。项目的 `/api/chat` 是固定检索问答流程，`/api/agent` 可以根据请求查知识、查题、分析题目、生成内容或读取学习记录。Agent 的部分工具内部仍然使用 RAG。

**项目证据：** [Agent 主循环](E:/StudyAgent/app/agent/agent.py)、[工具注册](E:/StudyAgent/app/agent/tools.py)。

### 15. Tool Calling 是模型直接执行 Python 吗？

**回答：** 模型返回工具名和 JSON 参数，服务端负责验证并执行对应函数。项目用 Pydantic 定义参数模型，通过同一模型生成 JSON Schema 并做运行时校验，防止工具说明和实际参数规则不一致。

**追问：模型返回不存在的工具或多余字段呢？** 注册表拒绝未知工具；参数模型按定义校验，多个工具参数模型还禁止额外字段。不能把模型返回内容交给 eval 执行。

### 16. 你的 Agent Loop 怎么运行？

**回答：** 首先构造 system 和 user 消息；规划器决定调用工具或返回最终答案；后端校验并执行工具，将结果作为 tool 消息回传；模型根据观察继续规划。直到完成、达到调用上限、上下文超限或服务错误。`tool_call_id` 把每条结果绑定到对应的模型调用。

**项目例子：** “解释 2025 期末第 12 题”可走 `search_questions → get_question → analyze_question → 最终回答`。多候选时应澄清，不能随意选一题。

**追问：是不是完整 ReAct？** 可以解释为受控的“选择工具—执行—观察”循环；项目没有展示隐藏推理，也没有额外实现复杂搜索式规划算法。

### 17. 当前有哪些工具？

**回答：** 共 11 个：知识检索、来源定位、历史题搜索、获取原题、分析题目、生成复习资料、生成模拟卷、读取学习进度、列出错题、创建复习计划、生成薄弱点复习资料。

**项目证据：** [TOOL_SPECS](E:/StudyAgent/app/agent/tools.py)。

**追问：为什么先查题再分析？** `analyze_question` 要求题目 ID 已进入本次执行上下文，避免模型凭空编造 ID；后端获取题目时仍验证课程与资料范围。

### 18. 怎么防止 Agent 无限循环和重复执行？

**回答：** 默认最多 6 次工具调用，并限制序列化执行消息的字符规模为 60000；一次模型响应带多个工具时，也计入总调用数。相同工具名加规范化 JSON 参数在本次 run 内复用缓存，并拒绝重复的调用编号。

**追问：这等于 exactly-once 吗？** 不等于。缓存只在一次执行中有效；失败后重试、客户端重复请求和新一次 run 仍可能重复创建内容，持久化幂等键尚未实现。

### 19. 工具失败后如何处理？

**回答：** 工具错误以结构化 observation 回传，让模型有机会修正参数或换工具。项目会恢复工具调用前的上下文字典，避免最终引用一个没有成功交给模型的来源；trace 保存错误状态与简要信息。

**追问：这会回滚数据库吗？** 不会自动回滚已经提交的外部副作用。上下文恢复、数据库事务和跨请求幂等是不同问题，工具内部仍需自己的事务与失败策略。

### 20. 多工具返回各自的 S1，怎么避免冲突？

**回答：** `ToolContext.cite` 按 Chunk ID 去重，对整个 run 统一编号。不同工具的本地 S1 会转换成执行上下文里的唯一引用编号，后续观察与最终回答共享同一个来源映射。

**项目证据：** [ToolContext](E:/StudyAgent/app/agent/tools.py)。

**追问：Agent trace 是思维链吗？** trace 展示工具名、参数、状态、结果数量和耗时，是可审计的执行记录，不包含模型隐藏推理。

### 21. 你实现了 Memory 吗？

**回答：** 一次 Agent run 有短期执行上下文；数据库保存问答结果、来源和工具轨迹快照，供用户回看。新问题仍独立检索，没有把历史自动注入规划器，所以尚未实现跨对话自动记忆。

**追问：怎么扩展长期记忆？** 可在用户授权范围内保存偏好或摘要，再按相关性读取；需要考虑过期、误记、隔离与预算。当前项目没有这部分实现。

## 三、数据库、可靠性与并发

### 22. 为什么 SQLite 和 Chroma 同时存在？

**回答：** SQLite 保存课程、文档正文、位置、题目与学习记录，是业务事实来源；Chroma 负责向量近邻检索，是可重建索引。业务状态与关联适合关系数据库，向量相似度检索交给专用索引，便于分别处理持久化和检索。

**追问：为什么不直接把全部业务放在向量库？** 题目关联、唯一约束、事务和学习统计需要关系数据能力；查询返回向量 ID 后，还要用业务库校验状态与范围。

### 23. 数据库事务的 ACID 怎么结合项目讲？

**回答：** 原子性保证一次事务里的修改整体提交或回滚；一致性维护约束；隔离性控制并发影响；持久性保证已提交数据按数据库保证保存。生成服务在完整校验后，用一次事务保存正文与来源快照，避免历史中出现半份成品。

**项目证据：** [生成服务](E:/StudyAgent/app/services/generation.py)、[试卷事务](E:/StudyAgent/app/services/exams.py)。

**追问：一次 session.commit 能保证 Chroma 一致吗？** 不能，SQLite 和 Chroma 不共享事务。

### 24. 数据库与向量库不能一起事务提交，怎么办？

**回答：** 采用状态限制可见性与失败补偿。先保存 processing；解析、向量写入完成后，才提交 Chunk 正文与 ready 状态；异常时回滚业务事务、尝试清理向量并标记 failed。查询只允许 ready 且指纹匹配的文档，所以残留向量不会成为可用证据。

**项目证据：** [入库状态机](E:/StudyAgent/app/services/ingestion.py)、[检索二次校验](E:/StudyAgent/app/rag/retriever.py)。

**追问：是不是分布式事务？** 没有实现两阶段提交。这里是针对本地双存储链路的状态隔离和补偿设计，不能宣称拥有跨库原子事务。

### 25. 服务在向量写入后崩溃，怎么恢复？

**回答：** 如果数据库尚未提交 ready，启动时会把遗留 processing 改为 failed，提示重试。重试先删除旧向量和 Chunk，再重新解析与入库。Chunk ID 根据文档 ID 和序号稳定生成，向量写入采用 upsert，减少重复残留。

**追问：自动继续上次进度吗？** 没有断点续跑；目前是检测中断、隔离状态、让用户重试。持久化任务队列是后续扩展。

### 26. 文件去重为什么用 SHA-256 和唯一约束？

**回答：** 文件名不能代表内容，我在流式保存时计算 SHA-256，数据库对 `(course_id, sha256)` 设唯一约束，因此同课程相同内容不能重复导入，不同课程允许分别上传。冲突时回滚并清理本次写入的文件。

**项目证据：** [上传接口](E:/StudyAgent/app/api/documents.py)、[Document 模型](E:/StudyAgent/app/models/__init__.py)。

**追问：先查询不存在，再插入，够不够？** 不够，两个并发请求都可能看到不存在；数据库唯一约束才提供最后的竞争保护。

### 27. 为什么只运行一个 worker？线程锁能跨进程吗？

**回答：** 当前导入、抽题、生成等模块用进程内 `threading.Lock` 控制竞争；锁只能协调共享这个锁的线程。多个 worker 各有独立锁和内存状态，不能据此保证业务互斥。项目明确定位单 worker，本机单用户使用。

**追问：如何扩展？** 将任务交给持久化队列，使用共享任务状态与幂等约束；按任务范围设计并发控制，再评估适合多写入的数据库。

### 28. SQLite WAL 有什么用？check_same_thread=False 呢？

**回答：** 项目启用 WAL，让读取和写入可以更好地并行；SQLite 仍同一时间只有一个写者。`check_same_thread=False` 取消驱动的同线程限制，适应 FastAPI 工作线程使用连接，但它并不让共享 Session 自动变得线程安全。项目按操作创建独立 Session，并开启外键检查。

**项目证据：** [数据库初始化](E:/StudyAgent/app/db/session.py)。

**参考：** [SQLite WAL 官方说明](https://www.sqlite.org/wal.html)。

### 29. 课程隔离怎么实现？是否等于用户权限？

**回答：** 用户请求提供 course_id 和可选 document_ids；后端验证文档是否属于课程，向量查询带课程和文档过滤，拿到 Chunk 后再次查询业务库确认归属、ready 状态和指纹。Agent 的范围由服务端注入，模型不能自行扩大。

**追问：有登录或多租户授权吗？** 当前没有。数据查询范围校验与用户身份授权不同，后续多用户必须验证用户对课程的访问权。

### 30. 题目和知识点如何建模？为什么题号不能做主键？

**回答：** 课程关联文档，试卷关联题目，题目和知识点通过中间表形成多对多。同卷不同大题可能都从第 1 题开始，不同试卷也会有相同题号，因此题号只用于搜索，具体操作使用唯一 question_id。知识点按课程和归一化名称去重。

**项目证据：** [数据库模型](E:/StudyAgent/app/models/__init__.py)、[知识点归一化](E:/StudyAgent/app/services/exams.py)。

**追问：同义词自动合并吗？** 当前仅做 NFKC、空白和大小写归一化，没有语义同义词合并或知识图谱。

## 四、Python 后端、HTTP 与安全

### 31. 为什么选 FastAPI？Pydantic 起什么作用？

**回答：** 项目需要清晰的接口和类型规则，FastAPI 配合 Pydantic 可以定义请求与响应模型、检查输入并生成接口文档。Pydantic 也用于配置、工具参数和模型输出结构校验，例如题数范围、题型枚举与选择题选项形状。

**追问：JSON 合法等于内容正确吗？** 不等于。结构校验只能保证字段符合约定，知识事实、题目答案和难度仍需证据校验与人工评价。

**参考：** [Pydantic 模型与验证](https://pydantic.dev/docs/validation/latest/concepts/models/)。

### 32. def 和 async def 怎么选？上传接口为什么同步？

**回答：** 项目使用同步 SQLAlchemy、`httpx.Client` 和格式解析库，路由主要写普通 def，由 FastAPI 在线程池运行。async def 适合可 await 的 I/O；如果在异步函数里直接调用阻塞库，会阻塞事件循环。同步路由保持了当前链路的实现一致性，但线程也会被长任务占用。

**追问：换 async 能让解析更快吗？** 不能自动加速 CPU 密集解析。大型处理应考虑进程或任务 worker；异步主要改善等待期间的调度。

**参考：** [FastAPI 同步与异步执行](https://fastapi.tiangolo.com/async/)。

### 33. 应用工厂、lifespan、Protocol 和上下文管理器怎么结合项目讲？

**回答：** `create_app(settings)` 可以创建不同配置的应用，测试传临时目录；lifespan 管理数据库、HTTP 客户端、索引及启动恢复；`with sessions()` 保证 Session 生命周期；`try/finally` 保证释放锁。Embedding 和 Planner 使用 Protocol 定义接口，demo 与 API 实现能按相同契约替换。

**项目证据：** [应用入口](E:/StudyAgent/app/main.py)、[Embedding 接口](E:/StudyAgent/app/rag/embedding.py)、[Planner 接口](E:/StudyAgent/app/agent/planner.py)。

**追问：为什么有利于测试？** 可以替换 Provider 或规划器，把外部服务的不确定性与业务流程分开验证。

### 34. HTTP 错误码与模型重试怎么设计？

**回答：** 上传成功返回 201，参数格式问题返回 422，冲突或忙碌返回 409，超限 413，格式不支持 415，资源不存在 404。外部模型超时映射 504，外部 HTTP 或非法输出通常映射 502。统一错误体带 code、message 和 request_id。

**项目证据：** [异常处理](E:/StudyAgent/app/main.py)、[Provider HTTP 封装](E:/StudyAgent/app/llm/compatible_provider.py)。

**追问：所有失败都重试吗？** 当前只对第一次 429 或 5xx 再请求一次，没有指数退避与 Retry-After 支持，也不会对超时自动重试。生成调用重试还可能带来重复计费。

### 35. 为什么流式读上传文件？如何控制路径和内容风险？

**回答：** 项目每次读取 1 MiB，累积检查大小并计算哈希，避免一次把完整上传内容读入应用内存。保存路径使用服务端 UUID；显示文件名去掉路径部分；下载前检查解析后的文件路径位于 uploads 目录。

**追问：扩展名验证是否足够？** 不够，扩展名只做第一层过滤，实际还需解析器识别；面向公网还应限制压缩解包规模、解析资源和请求频率。当前没有完整恶意文件防护或扫描能力。

### 36. API Key、模型热切换和前端 XSS 怎么处理？

**回答：** 配置使用 SecretStr 降低意外展示风险，连接描述不把密钥回传浏览器，前端不把密钥保存到 localStorage。密钥仍明文存于本地连接文件，SecretStr 不等于加密。模型切换检查活动请求数，忙碌时拒绝切换；配置先写临时文件再替换，避免留下半份 JSON。前端用户和模型文本用 textContent 渲染，降低被当作 HTML 执行的风险。

**项目证据：** [连接管理](E:/StudyAgent/app/services/connection.py)、[前端渲染](E:/StudyAgent/app/static/app.js)。

**追问：线上怎么改？** 使用用户权限、秘密管理与更完整的输入输出安全策略；不能把当前本地设计说成生产安全体系。

## 五、文档解析、生成和学习闭环

### 37. 三种文件格式如何统一？页码怎么来的？

**回答：** 解析器统一输出包含 text 与来源位置的 TextBlock。PDF 保存从 1 开始的物理页码，PPTX 保存幻灯片序号，DOCX 保存标题、段落或表格块索引。位置来自解析器，后续切块保留元数据。DOCX 排版页码依赖渲染，不能根据段落数量猜。

**项目证据：** [统一结构](E:/StudyAgent/app/schemas/document.py)、[格式解析器](E:/StudyAgent/app/rag/parsers/__init__.py)。

**追问：扫描 PDF 支持吗？** 当前没有 OCR，主要面向文本型 PDF；复杂双栏、公式和图片理解也有边界。

### 38. 模型提取试题时怎么防止改写或编造题干？

**回答：** 让模型返回原文 source_text，后端在对应窗口里定位连续匹配，只容忍空白差异；再验证选项来自题干、题号与原文开头一致，并把原文跨度映射回解析器位置。存储的题干使用匹配出的原文，而页码不由模型生成。

**项目证据：** [locate_quote 与窗口切分](E:/StudyAgent/app/services/exam_parser.py)、[抽题服务](E:/StudyAgent/app/services/exams.py)。

**追问：跨窗口长题怎么办？** 优先在题号边界切窗口，必要时重叠，并对重复跨度去重；超长跨窗口题仍可能遗漏。知识点和难度属于可出错的模型标注。

### 39. 试卷抽题失败为什么不撤销 RAG 入库？

**回答：** 文档索引和试题结构化是两种独立能力。文档完成 RAG 入库后，试卷再尝试抽题，抽题有独立状态与重试接口；抽题失败不会让已经可检索的原文失效。重解析先完成抽取，再在事务中替换题目，避免保存半套新题库。

**项目证据：** [入库后的抽题调用](E:/StudyAgent/app/services/ingestion.py)、[试卷状态与事务](E:/StudyAgent/app/services/exams.py)。

### 40. 生成复习资料和模拟卷如何保证符合要求？

**回答：** 每个明确主题独立检索，分配上下文预算，要求所有主题都有来源；生成时排除试卷资料，避免把题干中的待求结论当作答案依据。返回后校验主题覆盖、题数、题型、难度字段、引用归属和重复题干。全部通过才保存内容与实际输入的来源快照。

**项目证据：** [生成服务](E:/StudyAgent/app/services/generation.py)、[生成 Schema](E:/StudyAgent/app/schemas/generation.py)。

**追问：能保证题目答案正确和难度准确吗？** 不能。字段符合要求不等于事实正确；逐主题生成也不等于覆盖整门课程，当前没有完整出卷蓝图与质量评估。

### 41. 为什么生成记录、错题和对话要保存快照？

**回答：** 资料重建、题库重新解析或重新生成后，原始引用可能变化。快照保留当时的题干、作答、来源与结果，便于回看当时行为。导出读取已保存内容，不重新调用模型；无答案题目卷也不附来源原文，避免间接透露答案。

**追问：代价是什么？** 快照增加存储并保留旧信息，需明确版本与保留策略；原文件丢失时，来源文本快照不保证文件入口仍可打开。

### 42. 个性化学习是怎么做的？正确率如何计算？

**回答：** 当前根据练习自评和知识点标签统计。每次练习保存一条记录，同题错题本按 reference_key 聚合；再次出错增加错误次数并恢复待复习，正确重练标记掌握。正确率以每道不同题目的最近一次自评计算，薄弱主题来自未掌握错题中的标签统计，再据此安排计划或检索生成复习提纲。

**项目证据：** [学习服务](E:/StudyAgent/app/services/learning.py)。

**追问：是不是自动评分、能力模型或间隔重复算法？** 都不是。当前是规则式学习闭环，没有自动评分、知识追踪模型或经验证的自适应学习策略。

## 六、评估、优化与面试表达

### 43. 怎么评估 RAG？Recall、Hit Rate、MRR 分别是什么？

**回答：** Recall@K 是召回相关来源占标注相关来源的比例；Hit Rate@K 是至少命中一个相关来源的问题比例；MRR 是每个问题第一个相关结果排名的倒数再平均。答案还要独立评价事实正确、引用是否支持、无答案拒答、延迟与实际模型 usage。

**项目事实：** 已有报告用 3 份自编资料、24 条问题评估 demo，其中 20 条有答案；报告的文档级 Recall@6 为 42.5%、Hit Rate@6 为 50%、MRR 为 0.45。这是字词哈希检索基线，不能说成语义 RAG 问答准确率，也不能当作今天重新运行的结果。

**项目证据：** [评估方法](E:/StudyAgent/docs/evaluation.md)、[历史逐题报告](E:/StudyAgent/docs/evaluation-demo.json)。

### 44. Agent 和生成质量怎么评估？自动测试能证明什么？

**回答：** Agent 要分别测工具选择、调用参数、执行链路、任务完成和越界行为；生成要检查要求满足、证据支持、题目答案与实际难度。单元与集成测试验证确定性逻辑，模拟 HTTP 验证协议和异常，不等于真实模型能力验收。

**项目事实：** 已有 Agent demo 报告是 12 条问题首工具命中 12/12，属于规则路由；生成 demo 报告 4 个用例符合预期，验证摘录与保存流程。真实 LLM 工具选择、语义检索和生成事实质量仍待在线评价。

**项目证据：** [Agent 报告](E:/StudyAgent/docs/evaluation-agent-demo.json)、[生成报告](E:/StudyAgent/docs/evaluation-generation-demo.json)、[Agent 边界测试](E:/StudyAgent/tests/test_agent.py)、[失败恢复测试](E:/StudyAgent/tests/test_recovery.py)。

### 45. 项目的难点、优化顺序和当前边界怎么回答？

**回答：** 我的实现重点是让来源与执行状态可信：双存储失败恢复、多轮引用统一编号、模型输出校验、资料范围隔离。下一步先接入真实语义 Embedding 和模型，建立真实课程问题集并分析失败样本，再决定优化切块、召回或重排；有多用户和大文件需求时，再补持久化队列、身份权限和跨进程并发控制。

**追问：当前不能宣称什么？** 没有高并发线上成绩、语义准确率 95%、完整防幻觉、自动评分、跨对话长期记忆、OCR、BM25/Reranker 或成熟自适应学习算法。当前已有的是对应的本地业务实现与离线验证材料。
